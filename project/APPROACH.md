# Publishing approach

The approved diagram is the table of contents. A newcomer can follow the guided tour while an experienced reader can open one named decision directly. The text catalog and the map use the same lesson IDs, so changing the navigation never creates a second explanation.

## Working order

1. Inventory the feature and failure paths. Assign repeated representations of one concept to a canonical topic.
2. Establish the site, map and QA-to-UAT learning route. Test keyboard activation, readable labels and the failed QA route.
3. Author the linked Define, Build, Prove, Release and Learn lessons, plus roles and tools. Use public source material.
4. Run accuracy, confidentiality and editorial review. Repair findings and record residual limits.
5. Generate the static site and verify its routes under the project path. Bind the final reviewed state. A change to any authored content, map, site source or release definition invalidates that binding.
6. Publish the complete edition. A release tag selects the reviewed content version, notes and PDF snapshot.

The agents, site assets and workflow pattern are adapted from Vishal Khondre’s [AI SDLC Map](https://github.com/vishalkhondre/ai-sdlc-map/tree/60e0864f54b727eb582332ce1a4932ad89378266). The new content model uses fictional public worked examples, a delivery-oriented page template and one owner review at the end. The source record is portable across authors and sessions.
